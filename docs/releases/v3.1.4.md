## 更新内容

- 重做 macOS 看门狗：使用一个 NWPathMonitor 接收系统网络变化，配合每 30 秒一次的外网检测兜底。
- 修复断网检测或自动重连失败后停止看门狗、只能手动登录的问题；已经启动的看门狗会保留自动恢复能力。
- 网络断开立即显示“等待恢复 / 等待网络”，不发送认证请求；网络恢复或切换后防抖约 2 秒，再验证外网，必要时自动认证。
- 只有外网验证通过才显示“已连接”；首次登录失败不启动看门狗，旧请求的迟到成功结果不能覆盖当前断网状态。
- 重连临时失败按 15、30、60、120、300 秒退避，恢复联网后重置。手动注销、关闭看门狗或更换账号会取消自动恢复；明确的账号错误会暂停重试。
- 网络切换后的网页自动重连重新获取认证参数，学生端丢弃旧网络的客户端会话，避免复用旧 IP 或旧会话。
- 后台恢复使用进程内保存的成功账号凭据，不反复弹出 Keychain 授权。
- 新增项目功能逻辑说明，介绍登录、参数获取、外网验证、macOS 看门狗、注销、账号配置、多拨、启动、隧道与日志的行为和边界。
- 新增可复用的命令行 Release 脚本，使用项目钥匙串令牌，先上传草稿附件并核验 SHA-256，再公开发布。

## 验证与适用范围

- 网络与看门狗自动化回归测试通过，覆盖断开恢复、防抖、失败重试、冷却、停止、迟到回调和原有 5 秒检测限制。
- Release 构建、安装包解压及临时签名校验通过。
- 安装包适用于 Apple Silicon（arm64），最低 macOS 13。
- 自动化测试使用模拟网络；真实校园网和真实 Wi-Fi 切换仍需实际环境验收。

## 下载和使用

InterKnot Auth for macOS 安装说明

1. 解压这个 zip 文件。
2. 将 InterKnotAuth.app 拖动到“应用程序 / Applications”文件夹。
3. 第一次打开时，如果系统提示“无法打开，因为无法验证开发者”：
   - 先关闭这个拦截提示窗口，不要一直停留在弹窗里
   - 打开“系统设置”
   - 进入“隐私与安全性”
   - 在页面下方找到关于 InterKnotAuth.app 的拦截提示
   - 点击“仍要打开”或“允许打开”
4. 如果仍无法打开：
   - 在“应用程序”里右键点击 InterKnotAuth.app
   - 选择“打开”
   - 在弹窗中再次点击“打开”

说明：

- 这是未经过 Apple Developer ID 签名和 notarization 的测试版本，因此 macOS 第一次打开时可能需要手动允许。
- 应用需要访问校园网认证网关。使用自动获取认证参数时，请连接校园网络并关闭代理。
- 如果重新安装新版，请先退出旧版应用，再替换 Applications 里的 InterKnotAuth.app。
