# InterKnot Auth for macOS 功能逻辑说明

本文说明 macOS 版的实际行为与状态边界，便于使用、维护和验证。从 v3.1.4 起，看门狗使用 macOS 原生网络事件和低频兜底检测，不直接照搬 Windows 的网卡轮询实现。

## 1. 登录路由与认证

- “自动识别”模式下，账号以 `t` 开头时使用教师网页认证，其余账号使用学生客户端协议；判断不区分大小写。
- “教师/t 模式”强制使用网页认证。
- 网页认证读取网关页面，获取验证码，本地识别并构造 RSA 登录数据，提交到 `/ajax/login`。
- 自动验证码识别失败时请求手动输入；自动提交后网关明确返回验证码错误时，重新取图并切换到手动输入。
- 学生端探测客户端配置、协商加密算法、获取 ticket，再发送认证请求。网关返回有效会话后维护客户端心跳；注销使用会话提供的 term-url。
- 没有客户端配置的普通 HTML 页面不能证明已联网。学生端只接受原始联网探测地址的空 HTTP 204 作为已有外网连接的候选证据，之后仍需通过统一外网验证。
- 旧 keep-url、term-url 或 signature 的存在不能证明当前网络已经认证。

### 登录成功的判定

网关返回成功或已有在线状态后，程序立即执行外网连通性验证。只有验证通过，才显示“已连接”、保存成功账号记录，并在设置允许时启动看门狗。

首次登录失败、参数获取失败或外网验证失败时，不启动新的看门狗。已经建立过验证成功的监测会话，遇到临时网络故障则进入恢复流程，不能因为某一次失败而停止监测。

每次登录使用独立的任务代次。取消、注销、账号切换或网络切换后，旧任务的结果和日志不能覆盖当前连接状态。

## 2. 认证参数与 IP

- 自动获取向 `2.2.2.2`、189 和系统联网探测地址并发发送请求，整轮限制约 5 秒。
- 收到 HTTP Location 后先解析参数，再决定是否继续访问下一跳，避免最终页面打不开或后续跳转丢失参数。
- 兼容包含参数的 HTML URL、JS/meta 跳转及客户端 XML ticket-url，支持参数顺序不同与 HTML 转义。
- 从地址解析认证网关、`wlanacip` 与 `wlanuserip`；拒绝无效 IPv4 和 `0.0.0.0`，保留 HTTPS 网关协议。
- 获取成功时成组更新网关、AC IP 和认证 IP。失败时明确记录原因，不使用任意本机网卡 IP 冒充认证 IP。
- 手动解析接受浏览器跳转后的完整 URL。
- “自动更新认证 IP”开启时，网页登录前重新获取参数；学生协议自行从配置中获取 IP。
- 已启动的看门狗观察到网络切换后，下一次网页自动重连会强制刷新认证参数，即使普通登录的自动更新开关未开启，也不沿用旧网络的 IP。刷新失败保留重试，不提交旧参数。

已认证联网时，校园网可能不再提供认证跳转，因此自动获取失败并不等于没有物理网络。可在未认证环境获取，或使用已确认的跳转地址手动解析。

## 3. 外网访问检测

- 配置中的所有目标并发检测，整轮最多约 5 秒，包含 DNS、连接与响应等待；登录验证和看门狗验证任一目标成功即结束。
- “立即检测”展示各目标结果，每个目标完成后立即记录日志；未配置有效目标的手动检测不能证明联网。看门狗和登录验证在目标列表为空时使用内置目标。
- 默认 204 检测点要求 HTTP 204；Microsoft 和 Apple 默认探测点还校验预期内容。
- 禁止自动跟随重定向，因此校园网重定向到登录页不能被当作成功。
- 普通自定义目标要求 HTTP 2xx。自定义 HTTP 页面仍可能被透明代理以 HTTP 200 替换；建议保留内置探测点或使用可信 HTTPS 地址。检测目标不可达也可能只是目标被拦截，不能单凭它断言密码错误。
- 检测请求绕过系统 HTTP 代理；VPN/TUN 仍可能影响路由。正常 HTTPS 目标保持证书验证，证书错误不能当成联网成功。
- 手动检测失败会撤下“已连接”。若看门狗已启动，保留自动恢复并请求重连；若看门狗未启动，则显示失败，不擅自启动后台登录。

## 4. macOS 看门狗与自动恢复

### 设计原则

连接状态和恢复能力分别管理：“看门狗在监测”不代表“校园网已登录”。看门狗只在主账号登录并通过外网验证后启动。它的职责是在已建立的会话中持续发现失联，并安全地恢复连接。

原项目的参考原则是：网卡断开时保留监测，网卡恢复但外网不通时重连，临时网络错误不结束恢复流程。macOS 使用 `NWPathMonitor` 接收网络路径变化，而非每几秒主动扫描 Wi-Fi。

### 触发机制与开销

1. 只有一个 `NWPathMonitor`，监听系统网络路径，包括 Wi-Fi、有线网络和默认路由变化，不扫描 SSID，不申请读取 Wi-Fi 名称的权限。
2. 同样的可用状态、接口和本机 IPv4 快照会被去重；有变化则取消旧请求，重新开始约 2 秒防抖等待。
3. 路径不可用时不发检测或认证请求，仅等待系统通知。每 30 秒的兜底定时器仍会唤醒检查内部状态，但不会在已知断网时发送请求。
4. 路径恢复后等待约 2 秒，再进行一轮最多 5 秒的外网检测。系统路径可用只是允许尝试连接，不能直接把界面改为“已连接”。
5. 另有每 30 秒一次的低频兜底，发现 Wi-Fi 没断开但校园网认证已过期的情形。网络变化通知不是 SSID 切换的完整保证，兜底检测仍然必要。

这里没有忙等待。系统事件、低频定时器和异步请求共同工作。若网络通知连续变化，按最后一次有效变化重新计时，不为每次通知重复启动认证。

### 状态与动作

| 看门狗状态 | 连接状态与行为 |
| --- | --- |
| 未启动 | 尚未建立验证成功的监测会话，或用户已停止 |
| 监测中 | 最近一次外网验证通过；等待网络事件或下次兜底检测 |
| 等待网络 | 已撤下“已连接”，不发请求，保留恢复能力 |
| 检测中 | 检查真实外网连通性；网络切换后显示“等待恢复” |
| 正在重连 | 仅允许一项登录操作，连接卡片显示“登录中” |
| 等待重试 | 上次临时失败，连接卡片显示“等待恢复”，按退避间隔再试 |

路径恢复后的检测若证明外网已可达，则恢复连接显示，无需重复提交账号密码；这表示外网经过验证，不表示网关新建了本程序会话。若外网不通，才发起自动认证。认证返回成功后仍需再次验证外网，不能提前显示成功。

### 重试与停止边界

- 临时失败后按 **15、30、60、120、300 秒**逐步退避，之后维持 300 秒；每次到期先检测，若网络已通就不重复认证。
- 外网验证成功后重置退避；新的网络路径变化也会重置退避，防抖后尽快检查新网络。
- 缺网、超时、认证参数暂时获取不到、外网验证失败等都保留自动恢复能力。
- 明确的密码错误、账号不存在、未订购、操作过于频繁，以及用户未填写验证码等错误，暂停自动恢复，等待修正或手动登录。无法识别的响应按临时失败处理，仍受退避限制。
- 缺少必要字段、无效 URL 或 RSA 密钥不可用需要修正配置，不能无限自动提交。
- 用户点击注销、关闭看门狗、修改主账号或登录模式时，停止旧会话的恢复；取消仍在进行的自动登录，不能被旧回调重新拉起。
- 重新手动登录时暂停当前检测，防止两项认证并行。临时失败仍保留已经启动的看门狗。
- 关闭看门狗后，即使网络随后恢复，也不能自动登录。重新开启时只有仍处于已验证连接状态的会话会恢复监测，否则需手动登录。

### 凭据与学生端会话

自动恢复使用最近一次验证成功的主账号及密码快照，保留在进程内存中；不为后台重试反复弹出 Keychain 授权。即使未勾选“保存密码”，当前进程内仍可恢复；密码不会因此被写入磁盘。

网络变化时停止学生端旧心跳并丢弃旧客户端会话，避免把前一个网络的会话当作新网络的成功凭证。注销、主账号/模式切换和明确账号错误会清除自动恢复上下文。退出程序后该内存上下文自然结束。

## 5. 注销

点击注销先取消认证、检测、验证码等待和看门狗恢复，再尝试通知网关下线。即使网关下线失败，也不会自动登录回来。

网页登录使用本程序获取的 signature，学生端使用本程序会话的 term-url。外部客户端建立的在线会话可能缺少这些信息，因此应用不能保证代替外部客户端下线。网关认证候选成功但外网验证失败时仍保留可用的会话标识，便于尝试主动注销。

## 6. 账号、配置与密码

配置自动保存到用户 Application Support 中的 InterKnotAuth 目录。账号限制为单行英文字母和数字，账号历史去重并保留最近 12 项。

勾选保存密码时，验证成功后写入 macOS Keychain；未勾选则删除对应持久密码。启动和切换账号不主动读取密码，手动点击登录且密码为空时才按设置尝试读取，或使用“读取密码”操作。删除账号历史同时删除对应 Keychain 密码。

## 7. 多拨

按启用顺序逐项进行网页认证，使用每条线路的账号、密码和认证 IP。每条线路单独记录结果；整批结束不代表每条线路都成功。当前看门狗只管理已验证的主账号会话，不为每条多拨线路创建独立恢复控制器。

## 8. 开机启动与菜单栏

开机启动通过 macOS ServiceManagement 管理，设置与系统状态同步。启动后自动登录是独立开关，仅在允许保存密码且有账号时尝试；该次登录失败并不自动建立看门狗监测会话。

程序常驻菜单栏，不占 Dock。主窗口保持单实例，可从菜单栏恢复显示。

## 9. EasyTier 与 WebUI

EasyTier 服务端和客户端按配置启动本机 `easytier-core` 进程，程序记录进程输出；停止时终止该进程并关闭本地 WebUI。隧道状态与校园网认证状态是两项功能。

WebUI 监听 50000 端口。本机访问根路径显示状态，非本机根路径转到下载页。关闭“提供下载页”后拒绝下载入口；启用时可从当前 App Bundle 生成 zip 供下载。WebUI 不提供远程填写密码或执行登录的控制接口。

## 10. 日志与验证

界面日志保留最近记录并定期裁剪，落盘日志也限制大小。日志包含认证阶段、检测结果和恢复等待原因；不会记录登录密码。

`swift test` 包含 URLProtocol 模拟网络测试及可注入的网络监听/看门狗测试，覆盖断网不发请求、网络恢复、重复事件防抖、重试、停止后的迟到回调、旧成功结果隔离、定时兜底和账号错误分类。它们验证控制逻辑，不能代替真实校园网和真实 Wi-Fi 切换验收。

维护时如修改重试间隔、停止条件、登录成功判定或凭据生命周期，应同时更新本文和对应测试。


## 11. 命令行发布

版本号在 `Info.plist` 中维护。完成测试、Release 构建、临时签名和安装包校验后，将代码及版本标签推送 GitHub，再运行：

```sh
python3 scripts/publish_release.py \
  --tag v3.1.4 \
  --commit 完整的40位提交SHA \
  --asset release/InterKnotAuth_ForMac_v3.1.4.zip \
  --notes docs/releases/v3.1.4.md
```

脚本从 macOS 钥匙串读取账号 `github-release`、服务 `InterKnotAuthReleaseToken`，密钥不写入源码、文件或日志。发布前核对远端标签提交，先创建草稿并上传附件，检查大小与 SHA-256，最后公开发布。失败时保留草稿以便重试，不覆盖已发布的不同附件。环境若有权限审批，应按当前运行环境授权，不能从其他来源擅自读取替代凭据。
